## 01. Contexto de Negocio & Fricción Operativa

**Yanesu Shisutemu** es una plataforma transaccional de Punto de Venta (POS) y ERP desarrollada a medida para el comercio minorista y mayorista general (gestión de productos, proveedores, compras, categorías, inventario multimoneda y analítica de ventas). Adicionalmente, incorpora módulos verticales especializados como el **control de envases retornables y casilleros** para licorerías y distribuidores de bebidas.

El sistema fue concebido y opera activamente en producción sobre un **servidor VPS Cloud orquestado con Docker Compose**, manteniendo en paralelo una variante empaquetada para **Desktop con Tauri 2** para clientes que requieran aislamiento local:

### Separación de Responsabilidades en Cuatro Capas

El backend en Python 3.12 y FastAPI implementa una separación estricta para garantizar aislamiento transaccional y testeabilidad total:

1. **Controladores y Rutas (`app/routes/`):** Routers modulares (`sales.py`, `invoices.py`, `products.py`, `reports.py`, `exchange_rates.py`). Ciclo de vida HTTP y Server-Sent Events (SSE), inyección `Depends(get_db)` y mapeo de errores controlados.
2. **Servicios de Dominio (`app/services/`):** Lógica transaccional pura (`sales_service.py`, `invoice_service.py`, `gemini_service.py`, `broadcaster.py`, `exchange_rate_service.py`) coordinando operaciones bajo `db.commit()` y `db.rollback()`.
3. **Esquemas y Contratos (`app/schemas/`):** Validación en frontera con Pydantic v2 (`sale.py`, `invoice.py`, `product.py`, `exchange_rate.py`), garantizando coerción estricta a `Decimal` y rechazo de tipos flotantes.
4. **Persistencia y Modelado (`app/models/`):** Tipado declarativo en SQLAlchemy 2.0 (`sale.py`, `invoice.py`, `product.py`, `retornable.py`, `category.py`, `combo.py`) con `Mapped[...]` e integridad referencial `RESTRICT`.

### Decisiones de Arquitectura Registradas (ADRs)

- **ADR-001: Cloud VPS con Docker Compose como Arquitectura Principal y Tauri 2 como Empaquetado Local**  
  *Contexto:* La plataforma fue concebida primordialmente para despliegue en servidor VPS (acceso concurrente web, multiusuario y sincronización continua). Posteriormente se adaptó a Desktop para operar en entornos con requerimientos de aislamiento local.  
  *Decisión:* Docker Compose orquestando Nginx, FastAPI y PostgreSQL 16 como núcleo de producción, y Tauri 2 con sidecar FastAPI y SQLite embebida como empaquetado secundario de escritorio sin bifurcar la base de código.
- **ADR-002: Dualidad SQLite / PostgreSQL sin Bifurcación de Código**  
  *Contexto:* Soporte para PostgreSQL 16 en VPS Cloud y SQLite en modo Desktop y suite de pruebas.  
  *Decisión:* SQLAlchemy 2.0 unificado con Alembic en modo batch (`render_as_batch=True`) para aplicar migraciones relacionales idénticas en ambos motores.
- **ADR-003: Centralización de la Autoridad Financiera en el Backend**  
  *Contexto:* Tipos `number` de JavaScript sufren de imprecisiones IEEE 754.  
  *Decisión:* El frontend calcula subtotales solo para renderizado reactivo; el servidor FastAPI valida y sella los montos finales en `Decimal` antes del commit.

## 04. Desafíos de Ingeniería & Casos Límite

Durante la concepción y despliegue del sistema se superaron cuatro retos de ingeniería de alta complejidad:

### Reto 1: Mandato "Cero Floats" & Largest Remainder Method

El estándar IEEE 754 introduce imprecisiones de coma flotante (`0.1 + 0.2 = 0.30000000000000004`) inaceptables al liquidar impuestos y prorratear descuentos. Queda terminantemente prohibido el tipo `float` en toda la plataforma: cada variable monetaria se procesa mediante `Decimal(str(monto))` bajo redondeo bancario `ROUND_HALF_UP`.

```python
from decimal import Decimal, ROUND_HALF_UP

def quantize_currency(amount: Decimal | str) -> Decimal:
    """Cuantiza un monto monetario a exactamente 2 cifras decimales usando ROUND_HALF_UP."""
    if not isinstance(amount, Decimal):
        amount = Decimal(str(amount))
    return amount.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
```

</div>

Al distribuir un descuento global entre múltiples renglones, la sumatoria individual puede divergir por ±0.01 (*el dilema del centavo huérfano*). Para garantizar cuadre contable exacto, se implementó el **Largest Remainder Method (Hare-Niemeyer)**:

```python
from decimal import Decimal, ROUND_FLOOR, ROUND_HALF_UP
from typing import List

def distribute_amount_exact(total_to_distribute: Decimal, weights: List[Decimal]) -> List[Decimal]:
    """Distribuye un monto total entre ponderaciones garantizando suma exacta al centavo."""
    total_weight = sum(weights)
    if total_weight == Decimal("0"):
        return [Decimal("0.00") for _ in weights]

    # 1. Asignación base truncada al piso
    exact_shares = [(w / total_weight) * total_to_distribute for w in weights]
    floored_shares = [s.quantize(Decimal("0.01"), rounding=ROUND_FLOOR) for s in exact_shares]

    # 2. Residuo fraccionario en céntimos
    allocated_sum = sum(floored_shares)
    remainder_cents = int((total_to_distribute - allocated_sum) * Decimal("100"))

    # 3. Ordenamiento por mayor residuo y asignación de céntimos sobrantes
    remainders = [(i, exact_shares[i] - floored_shares[i]) for i in range(len(weights))]
    remainders.sort(key=lambda x: x[1], reverse=True)

    results = list(floored_shares)
    for i in range(remainder_cents):
        idx = remainders[i][0]
        results[idx] += Decimal("0.01")

    assert sum(results) == total_to_distribute, "La sumatoria debe cuadrar al centavo"
    return results
```

### Reto 2: Ingestión Asistida de Facturas: Human-in-the-Loop vs. Fuzzy Matching (Google Gemini API)

**Problema:**  
En el ecosistema comercial venezolano, las facturas y notas de entrega físicas emitidas por distribuidores mayoristas contienen descripciones sumamente heterogéneas, abreviaciones crípticas y jerga informal (*"BELMONT"*, *"CONSUL"*, *"LUCKY NOVA"*). Intentar resolver la concordancia de estos nombres contra el catálogo local mediante algoritmos de similitud de cadenas (*fuzzy matching* / distancia Levenshtein) provocó asociaciones erróneas con impactos destructivos en el stock de inventario.

**Solución Arquitectónica:**  
Se descartó la vinculación automática a ciegas en favor de un flujo asistido **Human-in-the-Loop** de alta velocidad. El servicio `app/services/invoice_service.py` ejecuta **dos llamadas desacopladas a la API de Google Gemini** para erradicar alucinaciones cruzadas: una para extraer metadatos globales (proveedor, número de documento, fecha, moneda) y otra para extraer la lista secuencial de productos y precios.

En la interfaz (React 19), los valores numéricos y fechas se precargan en inputs editables, mientras que la descripción textual original extraída por la IA se proyecta como **etiqueta de referencia visual fija arriba del selector** (`#1 BELMONT`, `#2 CONSUL`). Esto permite al usuario cotejar y vincular en segundos el producto exacto en su base de datos (`Buscar producto...`), con la posibilidad de hacer clic en la miniatura para inspeccionar la factura física en un modal ligero flotante sin cambiar de pestaña.

### Reto 3: Desacoplamiento de Conexiones DB en SSE (/stream) (&lt; 10 ms)

Para sincronizar la cotización del BCV en tiempo real mediante Server-Sent Events sin agotar el pool de SQLAlchemy (`QueuePool`), se aisló la consulta inicial a un destello de menos de 10 ms, cerrando la sesión antes de entrar al bucle asíncrono del evento:

```python
@router.get("/exchange-rates/stream")
async def stream_exchange_rates(
    request: Request,
    user: User = Depends(get_current_active_user),
    db: Session = Depends(get_db)
):
    # 1. Extracción veloz de cotización (<10 ms) y desacoplamiento de sesión
    latest_rate = db.scalars(
        select(ExchangeRate).order_by(ExchangeRate.fecha.desc()).limit(1)
    ).first()

    if latest_rate:
        db.expunge(latest_rate)
    db.expunge(user)
    db.close()  # Liberación inmediata de la conexión al pool

    # 2. Generador asíncrono vinculado al bus de memoria sin retener DB
    async def event_generator():
        queue = await event_bus.subscribe("exchange_rates")
        try:
            if latest_rate:
                yield f"data: {latest_rate.model_dump_json()}\n\n"
            while True:
                if await request.is_disconnected():
                    break
                new_rate_event = await queue.get()
                yield f"data: {new_rate_event}\n\n"
        finally:
            await event_bus.unsubscribe("exchange_rates", queue)

    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

### Reto 4: Ergonomía de Mostrador & Estado Global Bimoneda (React 19 + TypeScript + Zustand 5)

En operaciones de alta rotación, levantar las manos hacia el ratón ralentiza el despacho. Toda la experiencia de mostrador se gobierna mediante atajos de teclado físico (`F2` catálogo, `F10` cobro, `F9` orden en espera, `Escape` cancelar). Para evitar que los listeners globales provoquen re-renderizados continuos en el árbol de componentes, se implementó el hook `usePosKeyboard` utilizando referencias mutables desacopladas del ciclo de render:

```typescript
import { useEffect, useRef } from "react";

interface PosKeyboardHandlers {
  onSearchProduct?: () => void;   // F2: Catálogo instantáneo
  onOpenCheckout?: () => void;    // F10: Modal de cobro rápido
  onHoldOrder?: () => void;       // F9: Poner orden en espera (Hold)
  onCancelOrClose?: () => void;   // Escape: Cancelar / Cerrar modal
}

/**
 * Hook de bajo nivel para captura ergonómica de atajos físicos en mostrador.
 * Utiliza referencias mutables para desacoplar el listener global del ciclo de
 * renderizado de UI, eliminando listeners zombis y recargas de árbol.
 */
export function usePosKeyboard(handlers: PosKeyboardHandlers) {
  const handlersRef = useRef<PosKeyboardHandlers>(handlers);

  // Sincronizar handlers en caliente sin re-adjuntar el listener al DOM
  useEffect(() => {
    handlersRef.current = handlers;
  }, [handlers]);

  useEffect(() => {
    const handleKeyDown = (e: KeyboardEvent) => {
      const target = e.target as HTMLElement | null;
      const isInput = target?.tagName === "INPUT" || target?.tagName === "TEXTAREA";

      if (e.key === "F2") {
        e.preventDefault();
        handlersRef.current.onSearchProduct?.();
      } else if (e.key === "F10") {
        e.preventDefault();
        handlersRef.current.onOpenCheckout?.();
      } else if (e.key === "F9") {
        e.preventDefault();
        handlersRef.current.onHoldOrder?.();
      } else if (e.key === "Escape" && !isInput) {
        e.preventDefault();
        handlersRef.current.onCancelOrClose?.();
      }
    };

    window.addEventListener("keydown", handleKeyDown);
    return () => window.removeEventListener("keydown", handleKeyDown);
  }, []);
}
```

```typescript
import { create } from "zustand";

export type PackagingType = "UNIDAD" | "CAJA";

export interface CartItem {
  id: string;
  name: string;
  sku: string;
  packaging: PackagingType;
  unitsPerBox: number;
  quantity: number;
  unitPriceUsd: number;
  taxRate: number; // e.g. 0.16 para IVA 16%
}

interface CartTotals {
  subtotalUsd: number;
  taxUsd: number;
  totalUsd: number;
  totalVes: number;
}

interface CartState {
  items: CartItem[];
  exchangeRateBcv: number;
  addItem: (product: Omit<CartItem, "quantity">, quantity?: number) => void;
  updateQuantity: (id: string, packaging: PackagingType, quantity: number) => void;
  removeItem: (id: string, packaging: PackagingType) => void;
  clearCart: () => void;
  getTotals: () => CartTotals;
}

export const useCartStore = create<CartState>()((set, get) => ({
  items: [],
  exchangeRateBcv: 1.0,

  addItem: (product, quantity = 1) => {
    set((state) => {
      const existing = state.items.find(
        (i) => i.id === product.id && i.packaging === product.packaging
      );
      if (existing) {
        return {
          items: state.items.map((i) =>
            i.id === product.id && i.packaging === product.packaging
              ? { ...i, quantity: i.quantity + quantity }
              : i
          ),
        };
      }
      return { items: [...state.items, { ...product, quantity }] };
    });
  },

  updateQuantity: (id, packaging, quantity) => {
    set((state) => ({
      items: quantity <= 0
        ? state.items.filter((i) => !(i.id === id && i.packaging === packaging))
        : state.items.map((i) =>
            i.id === id && i.packaging === packaging ? { ...i, quantity } : i
          ),
    }));
  },

  removeItem: (id, packaging) => {
    set((state) => ({
      items: state.items.filter((i) => !(i.id === id && i.packaging === packaging)),
    }));
  },

  clearCart: () => set({ items: [] }),

  getTotals: () => {
    const { items, exchangeRateBcv } = get();
    const subtotalUsd = items.reduce((acc, item) => acc + item.unitPriceUsd * item.quantity, 0);
    const taxUsd = items.reduce((acc, item) => acc + item.unitPriceUsd * item.quantity * item.taxRate, 0);
    const totalUsd = Math.round((subtotalUsd + taxUsd) * 100) / 100;
    const totalVes = Math.round(totalUsd * exchangeRateBcv * 100) / 100;

    return {
      subtotalUsd: Math.round(subtotalUsd * 100) / 100,
      taxUsd: Math.round(taxUsd * 100) / 100,
      totalUsd,
      totalVes,
    };
  },
}));
```

### Aislamiento Riguroso y Casos Límite Auditados

El aislamiento de base de datos en `conftest.py` descarta mocks compartidos:
- **Bases Efímeras Aisladas:** Cada test genera un archivo temporal SQLite con `NamedTemporaryFile`, inyectado vía `app.dependency_overrides[get_db]` y destruido al concluir el caso.
- **Validación Estricta de Decimales:** Rechazo HTTP 422 inmediato ante valores con más de 2 cifras fraccionarias en importes y fijación exacta de 4 decimales en tasas BCV.
- **Desempaque Concurrente:** Verificación de atomicidad bajo peticiones simultáneas sobre unidades agotadas, impidiendo lecturas fantasma (*phantom reads*).
- **Control de Sobrepagos:** Respuesta HTTP 409 cuando los abonos superan el saldo adeudado en facturas de proveedores.

## 07. Conclusiones y Retrospectiva de Ingeniería

El despliegue productivo de **Yanesu Shisutemu** demuestra que las restricciones operativas del comercio real (bimonetariedad asimétrica, catálogos extensos y documentos físicos informales) se resuelven mediante arquitectura rigurosa y diseño centrado en el usuario:

1. **Flexibilidad Arquitectónica (Cloud VPS + Desktop Híbrido):** La orquestación con Docker Compose en servidor VPS centraliza la operación y analítica en tiempo real para múltiples terminales web, mientras que el soporte desacoplado para Tauri 2 asegura continuidad operativa local para clientes que requieran aislamiento sin bifurcar la base de código.

3. **Telemetría y Push-down SQL:** La refactorización analítica redujo la latencia media en un -65.8% y el tráfico en un -76.3%, delegando el trabajo pesado de costos y márgenes al motor relacional mediante SQLAlchemy 2.0.
4. **Inteligencia Práctica (Human-in-the-Loop):** La integración de visión multimodal con Gemini API resolvió el cuello de botella de compras sin caer en las trampas del fuzzy match ante la jerga informal de notas de entrega, reduciendo drásticamente los tiempos de carga de inventario con un cotejo asistido de alta precisión.
